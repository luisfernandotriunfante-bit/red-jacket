# Fluxo de desenvolvimento

1. Cada mudança nasce em uma branch própria.
2. Antes de abrir uma pull request, execute `npm run check`.
3. Não envie arquivos `.env`, senhas ou chaves privadas ao GitHub.
4. Novas telas devem usar os tokens de cor e espaçamento existentes.
5. Nenhuma tabela, dado de demonstração ou regra comercial deve ser criada sem definição aprovada.
6. Mudanças entram em `main` somente após revisão.
